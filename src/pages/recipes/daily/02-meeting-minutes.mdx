# 模拟案例：接待记录整理成纪要与待办

承办律师结束一次客户接待，手里有零散文字记录，需要整理成可编辑纪要并明确下一步。下面使用模拟文字，不涉及真实客户，也不假设 Kayak 已经自动录音或实时转写。

## 准备文字与材料清单

新建“模拟\_货款案接待”任务，添加两份文件：

* `接待记录.txt`：接待人员、时间和各方发言。
* `已收材料清单.txt`：合同复印件一份、付款回单一份；未收到完整对账单和验收记录。

接待记录可使用以下内容自行保存，也可直接作为任务文字提供：

```text
接待时间：2026年10月20日14:00。人员：张律师、林助理、甲公司王经理。
王经理：对方说已经付了10万元，我们财务暂时只找到一张8万元回单，付款用途还没核对。
张律师：先看合同约定和实际付款，暂时不能确认剩余款项，也没有承诺回款时间。
王经理：合同有复印件，验收记录需要问仓库，完整对账单还没拿到。
林助理：我先把收到的合同和回单做成目录。
张律师：王经理后续联系财务和仓库；什么时候能补齐，本次还没确定。
会议结束前未讨论是否立即起诉，也未确定谁负责发送催款函。
```

## 第一步：从原记录形成纪要

核对当前任务附件，发送下面的完整要求：

```markdown
请根据本任务的接待记录和已收材料清单，整理《货款案接待纪要》可编辑Word。
1. 写明模拟接待时间、参与人员、已收材料、讨论事项和待办。
2. 区分客户陈述、接待中已确认的安排，以及尚未核对的问题。
3. 对“对方称付10万元”与“目前找到8万元回单”并列记录，
   不自行确认实际付款或计算剩余货款，不把回单用途写成已查明。
4. 未讨论的诉讼决定、未承诺的胜诉或回款安排不补写。
5. 待办用表格列事项、负责人、完成时间、所需材料和当前状态；
   没有明确负责人或期限的，标为待确认，不自行指定。
6. 保留原记录，在工作副本中另存纪要，提供实际Word文件和保存位置。
7. 不发送给客户，不创建日程，不自动联系任何人。
```

先打开 Word 检查，而不是只看对话中的摘要。尤其检查“付款用途待核对”“补齐时间未确定”是否被保留，以及是否出现原记录没有的决定。

## 第二步：核对待办，避免补造安排

本例中可以列出的待办包括：林助理建立已收材料目录，王经理联系财务核对付款、联系仓库补验收记录。后两项未确定完成时间，应保留“待确认”。不能把“后续联系”改成“明日必须补齐”，也不能给未确定的催款函任务填上某位人员。

若记录本身不清楚，先要求列出疑问。例如“10万元是谁陈述、8万元回单是否对应本合同”，等待经办人员核对；不要求助手猜测发言人或补全会议结论。

## 第三步：收到确认后只更新有关部分

假设接待后经办人员补充：“已确认由王经理在2026年10月23日前提供财务对账结果，其他事项仍未确定。”在原任务继续：

```markdown
请在刚才纪要的付款核对待办中，补充负责人为王经理，
期限为2026年10月23日，并注明这是接待后追加确认。
原接待记录和会议日期不变，不把后续确认改写成当时已经达成的安排。
其他未确定事项保持待确认；另存v2 Word，并列出本次改动位置。
```

若途中发现改错内容，使用停止按钮后再说明修订范围；已经保存的纪要不会自动回滚，应比较版本。

## 产物验收

应取得实际可打开的纪要 Word，内含发言与事实状态、材料清单和待办表。检查 v2 只修改指定安排，原记录仍在，未自动发送、建立提醒或补写承诺。需要建立提醒时，应另行明确要求并核对日程。

手写图片或扫描件可能需要远程 OCR；敏感材料应先确认授权，禁止上传时在开始前明确仅本地读取。录音应先确认是否具有可用且获准的转写方式，再核对转写文字，不能由本案例推定客户端自动录音。
