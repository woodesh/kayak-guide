# 案例：签约前核对企业身份与公开风险

## 示例目标与材料

测试甲公司拟采购设备，报价、合同草稿与营业执照图片上的供应商名称不完全一致。甲公司希望先确认谁是签约方，再围绕交付和付款安排核对有关公开资料。实操时将下方占位内容替换为有权查询的企业全称或统一社会信用代码，先确认主体，再按返回记录开展核查。

准备以下5份材料，保留原始版本：

| 材料            | 用来确定什么问题            |
| ------------- | ------------------- |
| 设备采购合同草稿.docx | 合同相对方名称、签约人、交付和付款条件 |
| 报价单.pdf       | 报价主体与合同主体是否一致       |
| 营业执照图片.png    | 企业全称及信用代码；模糊字段需另行确认 |
| 供应商邮件摘录.txt   | 由谁解释名称差异，是否附有依据     |
| 采购需求表.xlsx    | 实际设备、服务和本次需要核对的资质事项 |

企业查询需先在企查查插件配置自己的API Key，并确认账号权益及查询、后续处理环境获准。Key只在密码配置框填写；Kayak余额不能代替企查查权益。仅做合同文本审阅时，可先完成不依赖企业查询的部分。

## 可复制的首轮任务

```text
我以采购方身份核对本次设备交易。真实企业全称为【名称】，
信用代码为【代码；不清楚则写待确认】，材料范围见本案5个文件。
先比较合同、报价与执照中的主体信息；不一致时列候选与差异，请我确认。
主体唯一确定后，查询基本登记，并围绕本次业务核对所需许可及相关公开风险。
范围为【明确事项及期间】，截至实际查询当日；不要无关全景调查或自动购买权益。
逐项记录来源、查询时间、记录日期、程序状态及与本合同的关系。
查到司法记录时按案号和阶段核对，不重复累计同一纠纷金额。
成功为空、无权限、积分不足、超时分别说明，未取得资料不补造。
出一份企业核对Excel及Word调查说明，列合同需要补充的身份、付款和履行问题。
登记信息不证明印章、签约授权或履约能力；不推定关联方共同承担债务。
若不能实查，先交付材料差异和待查清单，明确哪些查询尚未完成。
```

## 主体不明时先停在哪一步

不要让助手把名称“纠正”为搜索中最相似的公司。先核对信用代码、企业全称，以及报价方、签约方或分支机构各自角色。同名法定代表人也不能直接认定为同一自然人。

主体明确后，按合同需要查询。采购涉及特定许可时，核对许可范围和有效期；普通登记核对不必附加整套股权、历史档案或知识产权调查。完整历史档案等可选服务受单独配置与权益限制，拿不到时保留范围说明。

## 追加材料与修正范围

```text
供应商补交了清晰执照及“签约主体说明.pdf”。请先复核代码与名称，
说明哪些原候选可以排除，再继续获准范围内尚未完成的查询。
新增合同条款约定由另一家公司收款，请列出需核对的账户归属、
收款依据和合同安排，不从关联股东推定代收已获授权。
已有同范围查询结果可以复用；注明原查询日期，不为了更新报告重复收费查询。
```

如果旧查询时间已不能满足本次决策，应先说明需要更新哪项、为什么，再在授权范围内补查，而不是把旧资料标成今天查得。

## 成果与人工验收

应取得主体核对表、公开记录及状态表、材料差异与待查事项，并有实际可打开的Excel和Word。人工核对信用代码是否逐位正确、各名称是否属于同一主体，来源与日期是否保留；抽查命中记录原文，检查是否混淆诉讼与执行、申请与受理。

查询成功但为空，只能按本次范围说明未查见；连接或权限失败不能写成“无风险”。合同是否接受、是否要求担保及如何安排付款，仍须结合具体证据和商业选择审查。详见[插件配置](/start/04-plugin-activation)、[企业查询九类工作](/workflows/execution-audit/13-qcc-enterprise-data)和[记录核对与使用边界](/workflows/execution-audit/14-enterprise-investigation-boundaries)。
