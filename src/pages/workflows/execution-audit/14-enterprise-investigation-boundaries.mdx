# 企业调查：记录核对与使用边界

企业查询能提供登记、关联及公开风险线索。交付前要分清“查到了什么”和“这些资料能支持什么”，再结合原文书、实际交易材料和调查反馈继续判断。

## 保留来源、时间和查询范围

要求助手记录企业身份、资料来源、查询时间，以及本次查询的服务和时间范围。记录中同时出现公告日期、登记日期与事件日期时，应分别保留。

| 返回状态     | 应如何表达                       |
| -------- | --------------------------- |
| 查到记录     | 列明记录内容、日期和来源，继续核对其状态及与本案的关系 |
| 查询成功但无记录 | 说明在本次查询范围内未查见，不写成企业没有任何风险   |
| 权限或权益不足  | 说明本项资料尚未取得，不把缺失结果当作否定事实     |
| 超时或服务失败  | 说明本次未完成，不冒充一次有效的空结果查询       |
| 主体候选不一致  | 先核对名称、信用代码及登记身份，再继续查询       |

不同服务覆盖范围和更新时间可能不同。公开查询没有发现某项信息，不足以证明该事实从未发生。

## 关联路径与责任判断分开

共同股东、交叉任职、同地址或同类业务，可以帮助识别关联和提出调查问题。报告应写清具体是哪一种联系、来源是什么、发生在何时。

这些记录本身不能直接证明关联企业承担本案债务，也不能把丙公司名下财产直接列成乙公司的财产。是否采取相应诉讼或执行路径，应结合具体事实、证据、适用依据和程序分别研究。

可以这样提出任务：

> 请只画出有来源支持的关联路径。将公开登记记录与实际合同、付款及人员材料分开，列出仍需证明的事项，不把“可能有关联”改写成“应当承担债务”。

## 同一事项跨阶段记录不要重复累加

同一纠纷可能出现在一审、二审、执行等记录中，各阶段的案号和记载金额也可能不同。先核对当事人、案由、原文书及程序衔接，再判断是否属于同一事项。

例如，同一50万元纠纷在诉讼和执行阶段各有一条记录，不应直接合计成100万元负债。应要求助手标记重复或可能重复的记录，保留各阶段状态；无法确认的，不擅自合并，也不重复计入已经确认的汇总。

破产申请、公告、法院受理和程序终结同样需要分别表述，不能仅凭某一条申请记录写成企业已经进入相应程序。

## 公开企业数据与银行材料分开

企查查插件不提供银行账户余额或交易流水查询，也不替代法院财产查控。登记、担保或公开资产线索不能说明账户当前有多少钱，不能证明某项财产已经具备可执行条件。

你提供的合同、流水和回单可以用于付款核对，但仍应核对原始凭证、收付款主体、日期、流水号及交易用途。材料中有账户，不表示余额已知；有多份回单，不表示有多笔不同付款。

需要继续调查时，让助手整理线索来源、已知字段与待核查问题，再按具体案件和使用者权限办理。生成一份调查令申请书或法院审查稿，不等于已经获准查询、签发或采取措施。

## 三类延伸任务怎样保持事实边界

| 任务     | 应结合什么材料           | 避免直接得出的结论        |
| ------ | ----------------- | ---------------- |
| 签约前核查  | 企业登记、具体业务许可及合同条款  | 有登记或某项资质就一定有履约能力 |
| 劳动争议   | 劳动合同、工资、社保及实际用工材料 | 仅凭公开参保人数推定存在欠缴   |
| 知识产权核查 | 具体权利、类别、状态和相关争议材料 | 仅凭名称或外观近似认定侵权    |

## 确认数据可以进入后续处理环境

企查查 Key 属于用户自己的服务配置。切换 Kayak 登录账号不会自动更换它；多人使用同一个操作系统登录时，应先确认当前凭据和查询费用由谁承担。卸载插件也不等于已在企查查撤销 Key。

查询前按企查查约定和本单位要求确认使用环境；需要把结果用于云端模型、文书服务、网盘或其他外部应用时，也应确认后续处理范围获准。配置成功不代表所有材料都可以任意上传。

本地读取文件和发送材料给外部解析服务是不同操作。文档解析等可选服务未默认开启；如任务需要外部上传，先确认接收服务和材料范围。最后交付的报告应保留来源和事实限定，不把版式完整当作事实已经证实。
